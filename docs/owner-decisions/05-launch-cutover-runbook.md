# 5. Выкладка: отвязка страницы ожидания и остатки

Дата: 23.11.2026. Это пошаговый порядок для дня выкладки; пункт «отвязать Worker» нельзя сделать заранее, потому что
сейчас `regence.club` и `www` отдаёт именно Worker `regence-landing` (`ops/landing`).

## Что закрыто сейчас

| Пункт | Статус |
|---|---|
| Убрать `LEGACY_REFRESH_COOKIE` | **Сделано** (PR `chore/drop-legacy-cookie`): сайт не выкладывался, боевых сессий под старым именем нет; ждать 30 дней после выкладки не нужно. Если когда-то появится сайт с игроками под старым именем, вернуть поддержку не придётся: первый вход создаст новую сессию |
| Отвязать Worker от доменов | **При выкладке** — порядок ниже. Риск: между отвязкой и появлением A-записи сайт недоступен; порядок сводит это к минутам |

## Порядок в день выкладки

### 0. Подготовка (за день до; ничего не меняет у посетителей)
1. Сервер заказан, Docker и Compose стоят, `.env` заполнен (`DEPLOY.md`, п. 1), `PUBLIC_BASE_URL=https://regence.club`.
2. `docker compose -f docker-compose.prod.yml up -d`, миграции применены (`DEPLOY.md`, п. 2–3).
3. Проверка без DNS, через `--resolve`: `curl --resolve regence.club:443:<IP_сервера> https://regence.club/health`
   отвечает `200` (нужен сертификат: `DEPLOY.md`, п. 4; либо режим Cloudflare «Full (strict)» с Origin-сертификатом).
4. Снимок сервера и резервная копия базы сделаны; копия вне сервера работает (`DEPLOY.md`, п. 5).
5. Страницы `/privacy` и `/terms` с настоящими текстами опубликованы, письмо от почтового провайдера доходит.
6. Уведомить игроков бета-списка о времени (окно 15 минут).

### 1. Отвязать Worker (в этот момент сайт для посетителей пропадает)
Любой из способов:

- **Через панель:** Cloudflare → Workers & Pages → `regence-landing` → Settings → Domains & Routes → у `regence.club` и
  `www.regence.club` нажать «Remove».
- **Через проект:** в `ops/landing/cloudflare.config.ts` оставить пустой список `domains` (синтаксис проверить по `cf` при выкладке), затем `cf deploy` из папки
  `ops/landing`. (Скажите «отвяжи Worker» — я сделаю это с вашего разрешения в день выкладки.)

После удаления привязки Cloudflare стирает служебные записи, которые создал для Worker (в нашей зоне это заглушки
`AAAA 100::`). Если записи остались — удалить вручную в DNS.

### 2. Сразу добавить DNS (в течение минуты)
- `A  @    →  <IP сервера>`, облако **включено (Proxied)**.
- `CNAME  www  →  regence.club`, Proxied.
- SSL/TLS → **Full (strict)**.

### 3. Проверка
1. `https://regence.club` открывается, вход и регистрация работают, WebSocket-партия идёт (две вкладки).
2. Заголовки: `Set-Cookie: regence_refresh` с `Secure; HttpOnly; SameSite=Strict`.
3. `/health` и `/beta/config` отвечают. Sentry получает тестовую ошибку (если включён).
4. Резервная копия снимается; письмо сброса пароля приходит.

### 4. Откат (если сайт не поднялся за 15 минут)
1. Удалить `A @` и `CNAME www`.
2. Вернуть привязку Worker: в `cloudflare.config.ts` вернуть `domains: ["regence.club", "www.regence.club"]`, `cf deploy`.
3. Посетители снова видят страницу ожидания; разбираться с сервером без спешки.
